Linux: варианты бэкапа на NAS

  • Active Backup for Business (ABB) — бесплатный пакет Synology. Image-based backup с Changed Block Tracking. Агент ставится на Linux-машину (.deb/.rpm). Поддерживает только ext2/ext3/ext4/XFS — btrfs на клиенте не поддерживается. Ubuntu 24.04 работает с агентом v2.7+. Инкрементальные бэкапы, восстановление на уровне файлов или bare-metal.
  • rsync через SSH/SMB — универсальный вариант для любой файловой системы, включая btrfs. NAS A подключается как rsync-target. Можно настроить через cron: rsync -avz --delete /home/ user@nas-a:/volume1/LinuxBackup/. Не даёт bare-metal restore, но закрывает файловый бэкап.
  • Synology Drive Client — есть Linux-версия. Синхронизация папок в реальном времени. Подходит для рабочих файлов, но не для системного бэкапа.
⚠ Если Ubuntu стоит на btrfs — ABB agent не сможет сделать image backup. Используй rsync для файлов + отдельно бэкапь /etc, /home, список пакетов. Или переведи root на ext4.
Твоя конфигурация: Ubuntu 24.04 с RTX 5090. Если root на ext4 — ABB agent будет работать, включая инкрементальные образы. Для /home и рабочих данных можно дополнительно настроить rsync или Drive Client.

Windows: варианты бэкапа на NAS

  • Active Backup for Business (ABB) — основной вариант. Поддерживает Windows 10/11 все редакции, Server 2016–2025. Image-based backup с VSS-based Changed Block Tracking. Bare-metal restore, восстановление отдельных файлов, восстановление в VM (VMware/Hyper-V/Synology VMM).
  • Synology Drive Client — файловая синхронизация, как Dropbox. Для рабочих папок.
  • Windows File History — встроенная, можно направить на SMB-шару NAS. Но ABB лучше: и система, и данные, и bare-metal.
ABB на DS224+ бесплатен и не требует лицензий. Все бэкапы дедуплицируются на уровне блоков — 10 машин с Windows 10 займут не 10× места, а значительно меньше.

Где фото хранятся на NAS (и есть ли дубли)

При текущей схеме одно и то же фото с iPhone может оказаться в трёх местах на NAS A:

  • Synology Photos — прямой upload с iPhone. Фото лежит как файл в папке /photo/.
  • Encrypted iPhone backup — внутри бэкапа, созданного Finder на Mac Mini. Это один большой зашифрованный blob, фото из него не извлекаются отдельно.
  • Time Machine (Mac Mini) — внутри TM-снимка Mac Mini, который хранит iCloud Photos Library с оригиналами. Фото внутри TM sparse bundle.
Реальный overhead: Synology Photos хранит фото как обычные файлы (полный размер). iPhone backup — это monolithic blob (~30–60 ГБ на устройство, включая всё, не только фото). Time Machine инкрементальна — после первого полного снимка занимает мало места. Итого: дублирование фото добавляет примерно 15–20% от объёма фото-библиотеки. При библиотеке в 500 ГБ это ~75–100 ГБ «лишнего» — не критично на 10 ТБ RAID1.

Можно ли убрать дубли?

  • Вариант 1 (рекомендуемый): не трогать. Три копии — это три разных уровня защиты. Synology Photos = быстрый доступ с телефона. iPhone backup = полное восстановление устройства. TM = историческая лента версий. Если что-то сломается в одном месте — два других страхуют.
  • Вариант 2: исключить Photos Library из Time Machine. В настройках TM на Mac Mini добавить ~/Pictures/Photos Library.photoslibrary в исключения. Экономит место, но теряется версионирование фото через TM.
  • Вариант 3: отключить Synology Photos auto-upload. Фото будут приходить только через Mac Mini (iCloud → Mac Mini → TM/Drive → NAS). Убирает прямой поток, но добавляет зависимость от Mac Mini для фото — если он выключен, фото не бэкапятся.

Мой совет

Оставить все три потока. 75–100 ГБ «лишнего» на 10 ТБ — это менее 1% общего объёма. Зато Synology Photos работает напрямую (не зависит от Mac Mini), iPhone backup даёт полный restore устройства, а TM даёт историю. Разные задачи — разные копии.

Если объём фото-библиотеки вырастет до 2+ ТБ, тогда имеет смысл исключить Photos Library из TM (вариант 2).

Ubiquiti (сеть) Mac Mini NAS Linux/Windows Wi-Fi клиенты

Шаг 1: Покупки

  • 2 × Synology DS224+
  • 4 × WD Red Pro 16 TB (WD161KFGX)
  • Mac Mini M4 16 ГБ / 512 ГБ
  • Ethernet-кабели Cat 6

Шаг 2: NAS A

  • DSM → Storage Pool (RAID1, Btrfs) → shared folders: Photos, Drive, TimeMachine, ABB
  • Пакеты: Synology Photos, Synology Drive Server, Active Backup for Business, Snapshot Replication, Hyper Backup
  • Time Machine service: Control Panel → File Services → SMB → Enable TM
  • ABB: активировать (бесплатно с Synology Account)

Шаг 3: NAS B (off-site)

  • DSM → Storage Pool (RAID1, Btrfs)
  • Принимает Snapshot Replication (настроить на NAS A → target NAS B)
  • Принимает Hyper Backup (NAS A → Remote NAS → NAS B)
  • Расписание: Snapshots каждые 15–60 мин, Hyper Backup раз в день

Шаг 4: Mac Mini M4

  • Ethernet к NAS A (или роутеру)
  • Apple Account → iCloud Drive + Photos → «Download Originals»
  • Synology Drive Client → sync на NAS A
  • Time Machine → NAS A
  • Energy → не засыпать с выключенным дисплеем
  • Screen Sharing → вкл (управление с MacBook)
  • Finder → iPhone → Trust → Wi-Fi sync → Encrypt local backup

Шаг 5: iPhone / iPad

  • Synology Photos (App Store) → Auto Upload вкл
  • Проверить: Finder на Mac Mini → Wi-Fi sync + encrypted backup

Шаг 6: MacBook

  • Time Machine → NAS A (Wi-Fi)
  • Screen Sharing: vnc://[mac-mini-ip]

Шаг 7: Linux (Ubuntu)

  • Если ext4: скачать ABB Agent v2.7+ (.deb) → sudo ./install.run → sudo abb-cli -c → указать IP NAS A
  • В DSM ABB: создать задачу для Linux-машины, задать расписание
  • Если btrfs или доп. файлы: crontab -e → 0 2 * * * rsync -avz --delete /home/ user@nas-a:/volume1/LinuxBackup/
  • Опционально: Synology Drive Client (Linux .deb) для real-time sync рабочих папок

Шаг 8: Windows

  • Скачать ABB Agent (exe) из DSM → установить → указать IP NAS A
  • В DSM ABB: создать задачу, включить image-based backup + расписание
  • Опционально: Synology Drive Client для файловой синхронизации

Шаг 9: Проверка всех потоков

  • ☐ iPhone фото → Synology Photos на NAS A
  • ☐ Mac Mini TM backup → NAS A
  • ☐ MacBook TM backup → NAS A
  • ☐ iCloud Drive файлы → Drive на NAS A
  • ☐ Encrypted iPhone backup → Finder на Mac Mini → TM → NAS A
  • ☐ Linux → ABB / rsync → NAS A
  • ☐ Windows → ABB → NAS A
  • ☐ Snapshot Replication → NAS B (проверить в DSM NAS B)
  • ☐ Hyper Backup → NAS B (задача без ошибок)
